# 天韵艺术 · 钢琴学校品牌管理平台 —— 整体方案

> 版本：v1.0（方案规划稿）
> 日期：2026-08-11
> 定位：以「钢琴一对一/小组课」为核心，覆盖招生→教务→教学→消课→营收→品牌增长的全链路 SaaS 平台

---

## 一、项目定位

| 维度 | 说明 |
|---|---|
| 目标 | 用一套系统同时服务校长、教务/后台、教师、学生与家长四个角色 |
| 核心 | **课时计算（消课）是业务命脉**，围绕它构建排课、考勤、反馈、课酬、报表 |
| 品牌 | 前台官网+品牌展示+试听课预约，提升品牌形象与招生转化 |
| 形态 | Web 管理后台 + 微信小程序（家长/教师端）+ 品牌官网（响应式 Web） |

---

## 二、用户角色与权限（RBAC）

| 角色 | 主要入口 | 核心诉求 |
|---|---|---|
| 校长（老板） | Web 管理后台 | 看经营数据：营收、消课、续费、出勤、教师课酬；管权限 |
| 教务/运营（后台管理） | Web 管理后台 | 排课、调课、学员档案、收费、课时包、请假审批、通知 |
| 教师 | 教师小程序/App | 看我的课表、点名、写课后反馈、布置作业、查课酬 |
| 学生/家长 | 家长小程序 | 看课表、请假、查剩余课时、看反馈与作业、缴费记录 |
| 访客（潜在学员） | 品牌官网 | 品牌了解、课程/师资介绍、预约试听课 |

权限建议：按「角色 + 数据范围（本校/本校区/本人）」设计，校长可给教务/教师分配不同权限。

## 三、功能模块设计

### 1. 品牌官网（对外）
- 品牌介绍、课程体系（钢琴一对一、小组课、考级辅导）、师资团队
- 校区与教室展示、学员成果/音乐会/考级通过率
- 试听课在线预约（表单→自动生成线索，进入教务系统）
- 家长口碑、转介绍活动页、公众号/小程序跳转入口

### 2. 教务管理（后台）
- 学员管理：档案、合同、缴费记录、剩余课时、成长记录
- 课程体系：课程类型、课时单价、课时包（含赠课）、有效期
- 排课：周课表/月课表、教师教室时间冲突检测、批量排课、调课/补课
- 考勤：上课点名、迟到早退、未到处理（扣/不扣课时规则）
- 请假/停课：家长端申请→教务审批→自动改期或保留课时
- 教师管理：教师档案、授课时段、课酬方案、请假、离职交接

### 3. 课时计算（核心，单独说明）
- 课时账户：每个学员一个课时账户，支持多个课时包（买一送一、有效期不同）
- 扣课时规则：一对一按 1 课时/节；小组课按比例折算（可配置）
- 消课触发：教师/教务点名确认后自动扣减，可撤销（防误操作）
- 冻结/解冻：请假、停课期间课时冻结，不扣减
- 有效期提醒：临期课时包提前提醒家长续费
- 报表：消课明细、剩余课时、课时消耗率、应消/实消对比

### 4. 教学管理（教师端）
- 我的课表（今日/本周）、上课提醒
- 点名签到（上课前 30 分钟可操作）、一键联系家长
- 课后反馈：课堂内容、学员表现、练习建议（自动同步给家长）
- 作业布置与点评、练琴打卡查看
- 学员档案（教学备注、考级进度）
- 课酬：按课时/按学员/按比例方案，月度课酬明细与结算

### 5. 学生/家长端（小程序）
- 查看课表、上课提醒、在线请假（自动流转审批）
- 剩余课时/课时包明细、缴费记录与电子收据
- 查看教师课后反馈、作业、练琴打卡
- 在线续费/购买课时包（可接微信支付）、续费提醒
- 消息通知：排课变更、请假结果、课时不足、活动通知

### 6. 校长/管理层（数据驾驶舱）
- 今日概况：上课数、到课率、新增学员、当日营收
- 经营报表：月度营收、消课收入、续费率、退费率、转介绍率
- 教师维度：课时数、课酬、家长满意度（反馈评分）
- 学员维度：消课进度、活跃度、流失预警（连续 N 周未上课）
- 对比分析：本月 vs 上月、校区/教师排行

### 7. 后台管理（系统级）
- 账号与权限（RBAC）、操作日志
- 校区/教室/课程基础数据配置
- 消息模板（短信/公众号/小程序订阅消息）
- 系统设置：扣课规则、请假规则、有效期规则等参数化配置

## 四、课时计算业务规则（关键设计）

```
课时包(购买) → 学员课时账户(可含多个包) → 上课点名 → 自动/手动消课 → 剩余课时
```

规则点：
1. 每节课默认扣 1 课时；小组课按「课程系数 × 实际时长」折算，系数可配置。
2. 支持赠课（买 10 送 2），先扣正课再扣赠课（或按比例扣，可配置）。
3. 请假须在上课前 N 小时（默认 4 小时）申请，审批后不扣课时；临时请假/缺席按规则扣（可配置）。
4. 点名后 24 小时内可撤销消课，超时需校长/教务权限。
5. 课时包独立有效期，过期自动冻结并提醒续费；结转/续费规则可配置。
6. 所有消课动作留痕：谁、何时、哪节课、扣了哪个包、可否撤销。

## 五、技术方案

### 推荐架构
```
┌─────────────────────────────────────────────┐
│  客户端层                                      │
│  品牌官网(Web) / 教务后台(Web) / 家长小程序     │
│  教师小程序 / 校长数据看板(Web)                 │
└───────────────┬─────────────────────────────┘
                │ HTTPS
┌───────────────▼─────────────────────────────┐
│  接入层：Nginx + 微信小程序/公众号/支付 网关      │
└───────────────┬─────────────────────────────┘
┌───────────────▼─────────────────────────────┐
│  应用层（微服务/模块化单体均可）                  │
│  用户权限 / 学员 / 课程排课 / 课时账户 / 消课     │
│  考勤反馈 / 作业 / 报表 / 通知 / 支付订单         │
└───────────────┬─────────────────────────────┘
┌───────────────▼─────────────────────────────┐
│  数据层                                       │
│  MySQL(业务) + Redis(缓存/分布式锁防重复消课)     │
│  OSS(课件/视频) + 消息队列(通知) + 定时任务(提醒)  │
└──────────────────────────────────────────────┘
```

### 技术选型建议（二选一）
| 方案 | 适用 | 栈 |
|---|---|---|
| A. 快速落地（推荐中小机构） | 预算有限、1-3 个月内上线 | 前端 Vue3 + Element Plus；后端 Node.js(NestJS) 或 Java(Spring Boot)；MySQL 8 + Redis；小程序用 uni-app 一套代码出微信/支付宝 |
| B. 长期扩展 | 连锁校区、多门店扩张 | 微服务拆分（用户/教务/课时/报表/通知）+ 数据仓库(ClickHouse) 做经营分析 |

### 关键提示
- 小程序优先做「家长端 + 教师端」两个入口，共用一套后端。
- 课时扣减用「数据库事务 + Redis 锁」防止并发重复扣课时。
- 定时任务负责：上课前提醒、课时不足提醒、课时包到期提醒。
- 所有关键操作（消课、退款、改价）写操作日志，方便对账。

## 六、数据模型概要（核心表）

- users / roles / permissions（用户、角色、权限）
- students / parents（学员、家长绑定）
- teachers / staff（教师、员工）
- courses / course_packages（课程、课时包）
- schedules（排课表）
- classes / class_attendances（课次、考勤点名）
- lesson_accounts / lesson_transactions（课时账户、课时流水）
- orders / payments（订单、支付）
- leaves（请假申请）
- feedbacks / homework / practice_checks（反馈、作业、练琴打卡）
- reports（报表缓存/汇总）

## 七、开发路线图（建议分三期）

### 第一期 MVP（约 6-8 周）——先跑通核心闭环
- 后台：学员、课时包、排课、点名消课、请假审批
- 家长小程序：课表、剩余课时、请假、缴费记录
- 教师小程序：我的课表、点名、课后反馈
- 校长看板：营收、到课率、消课率基础报表
- 上线：1 个校区试点，人工运营

### 第二期 V1（约 8-12 周）——品牌与体验
- 品牌官网（品牌展示 + 试听课预约 + 线索管理）
- 作业/练琴打卡、家长满意度评价
- 微信支付在线续费、电子收据
- 通知体系（公众号/短信/订阅消息）
- 课酬结算模块

### 第三期 V2（约 12 周+）——数据与扩张
- 经营驾驶舱升级（流失预警、续费预测、教师排行）
- 多校区/多门店支持
- 考级/比赛/音乐会专项管理
- 数据大屏（前台/校长办公室展示）

## 八、团队与预算估算（人民币，参考）

| 项目 | 估算 |
|---|---|
| 自建开发（外包/自研团队） | MVP 约 8-15 万；全套三期约 30-60 万 |
| 人力 | 产品 1 + 前端 1-2 + 后端 1-2 + 测试/运维 0.5-1（MVP 期 4-5 人） |
| 年运维 | 云服务器+域名+短信+微信认证等约 0.5-2 万/年 |
| 备选 | 先采购成熟教务 SaaS（如校管家、小麦助教等）+ 自建品牌官网，成本最低，但个性化弱 |

> 建议：若想快且省，可「SaaS 先跑业务 + 自建官网/小程序做品牌」；若想深度定制，按三期路线自建。

## 九、风险与建议

| 风险 | 建议 |
|---|---|
| 消课规则不清导致纠纷 | 上线前把扣课/请假/赠课规则写成制度并公示，系统参数化 |
| 数据迁移/历史课时混乱 | 试点期人工核对，支持批量导入与手工修正 |
| 教师/家长使用意愿低 | 做轻量好用的小程序，减少学习成本；给教师课酬对账作为激励 |
| 开发延期 | MVP 严格切范围，二期再上品牌官网 |
| 微信生态合规 | 小程序类目与资质（教育/培训）提前准备，避免审核卡点 |

## 十、下一步行动（建议）

1. 确认范围：是否包含在线支付、是否连锁多校区、是否需要品牌官网先行。
2. 整理业务规则：现有一对一/小组课课时单价、赠课规则、请假规则。
3. 选择路线：自建 vs SaaS+自建官网 vs 全外包。
4. 出原型：先做 5-8 个核心页面的高保真原型（后台课表、家长端课时页、校长看板）。
5. 立项开发：按第一期 MVP 排期启动。
